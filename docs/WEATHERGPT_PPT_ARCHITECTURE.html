⚡ Slide 2: End-to-End Working Flow of the App

PPT Slide 2

Step-by-step end-to-end data lifecycle: from the moment a user asks a question to database persistence and multi-modal feedback.

Step 1: User Query & Multi-Modal Input

The user inputs a query via Voice (Indic Speech-to-Text) or Text (e.g., "What should I do with my cotton crop today?" in Telugu or Hindi) and selects their persona (Farmer, Pilot, NDMA, Citizen).

Step 2: Geocoding & MongoDB Geospatial Cache Check ($near / 2dsphere)

The backend resolves the user's location to GeoJSON coordinates [lon, lat] and executes a fast query against MongoDB weather_cache collection using $near with a 5km radius. If cached within 15 minutes, it returns immediately without burning API quotas.

Step 3: Live NWP Sensor & Radar Ingestion (On Cache Miss)

If not cached, the server concurrently fetches high-precision numerical weather forecasts (temperature, humidity, precipitation, wind gusts) from Open-Meteo, air quality metrics (PM2.5, US AQI), and disaster cyclone advisories from GDACS.

Step 4: IMD Risk & Hazard Rule Computation

The internal rule engine computes the IMD Extreme Weather Risk Score (0-100), checks gust thresholds for Gale/Squall warnings, and generates color-coded caution badges (Green, Yellow, Orange, Red Alert).

Step 5: Context Grounding & Trained AI Model Inference

The live telemetry, IMD risk metrics, and persona profile are assembled into a Strictly Grounded Prompt and passed to the Domain-Trained AI Model (backed by the custom AI API Key). The model interprets the data using its Agromet/meteorological weights and formats the response in the chosen Indian language.

Step 6: MongoDB Persistence & Training Dataset Logging

The fresh weather telemetry is cached in MongoDB with an auto-expiring TTL index (900s). The interaction is logged into ai_conversations and flagged for continuous training/RLHF improvement in training_dataset.

Step 7: Multi-Platform Presentation & Indic Audio Readout

The JSON response is delivered back to the client. The Flutter / Web UI renders the decision cards, plots Doppler radar reflectivity, and triggers the Web Speech Synthesis engine to speak the answer aloud in the user's regional dialect.

🍃 Slide 4: MongoDB NoSQL Database Architecture

PPT Slide 4

Why MongoDB is the ideal database for modern weather intelligence systems: flexible geospatial document schemas, high-throughput telemetry writes, and auto-indexing.

📁 MongoDB Collections & Schemas

  • 1. weather_cache
    Stores weather & AQI payloads. Indexed with 2dsphere on location: { type: "Point", coordinates: [lon, lat] } and TTL index on expiresAt (900 seconds).
  • 2. ai_conversations
    Audit log storing user prompt, AI synthesized response, language code, persona, telemetry snapshot, and user helpfulness rating.
  • 3. training_dataset
    Curated prompt-completion pairs from real farmer and meteorologist interactions used to continuously re-train and benchmark the AI model.
  • 4. favorite_places
    User-pinned cities and villages with GeoJSON points for rapid 1-click dashboard switching.
  • 5. user_settings
    Secure user preferences: selected vernacular language, auto-TTS state, encrypted AI API key, and default persona.

🚀 Technical Advantages for SIH Judges

  • GeoJSON 2dsphere Spatial Queries: Efficiently finds weather data for nearby villages using MongoDB's native $near and $geoWithin operators.
  • TTL (Time-To-Live) Auto Invalidation: Documents automatically expire after 15 minutes, maintaining strict meteorological freshness without manual cron scripts.
  • Horizontal Scalability (Sharding): Capable of storing millions of sensor readings across Pan-India weather stations effortlessly.
  • Native JSON Document Model: Seamlessly ingests complex nested weather forecasts and satellite telemetry without rigid SQL table migrations.
