1. Executive Summary & SIH Alignment

1.1 Problem Statement (SIH26068)

In India, meteorological information is predominantly disseminated through fragmented numerical reports, static satellite imagery, or English-language press releases. Crucial stakeholders—including smallholder farmers, local emergency relief teams (NDMA/SDRF), and transport workers—face severe bottlenecks:

  • Cognitive Overload: Raw numbers (e.g. 1012 hPa, 78% RH, convective CAPE) are incomprehensible to non-meteorologists.
  • The Generic AI Hallucination Problem: Standard conversational LLMs (e.g., off-the-shelf ChatGPT) invent weather values and hallucinate precipitation chances, creating lethal risks during severe weather.
  • Language & Literacy Barriers: India's rural agricultural workforce requires information in local vernacular tongues (Telugu, Hindi, Marathi, Kannada, Tamil) via spoken audio.
  • Lack of Actionable Advice: Raw metrics are not translated into operational directives (e.g., whether to delay pesticide spraying to avoid drift or postpone canal irrigation).

1.2 The Weather SPT Solution

Weather SPT (Smart Predictive Telemetry) solves this crisis by introducing a strictly grounded, multi-tier weather intelligence platform. Built with a Flutter AMOLED front-end, Node.js REST API gateway, MongoDB Atlas geospatial database, and a domain-trained AI engine, Weather SPT guarantees zero-hallucination accuracy, two-way vernacular voice support, 30-day climate anomaly analytics, and real-time Doppler radar simulation.

Core Architectural Principle: Grounded Telemetry First, Generative AI Second
Weather SPT never permits the AI model to invent weather data. Instead, live satellite and NWP telemetry is fetched first, validated by deterministic algorithmic risk rules, and fed to the AI strictly as immutable boundary constraints. The AI acts solely as an analytical reasoning and natural language synthesis engine.

2.1 Detailed Execution Steps

PHASE 1
Multi-Modal Ingestion & Speech Recognition

The user interacts through the Flutter mobile app or PWA web interface using either keyboard text or microphone voice input. If voice is selected, the Web Speech API / mobile audio pipeline captures the spoken waveform and transcribes it into localized text in one of 6 supported languages (English, Telugu, Hindi, Marathi, Kannada, Tamil). The user's active persona (Citizen, Farmer, Pilot, NDMA Officer) is simultaneously attached to the request payload.

PHASE 2
Geocoding & MongoDB Atlas Geospatial Cache Check

The system resolves the query place name or device GPS coordinates into high-precision Latitude and Longitude. Before initiating expensive third-party meteorological API requests, the Node.js backend queries MongoDB Atlas collection weather_cache using a GeoJSON 2dsphere spatial query with the $near operator within a 5 km radius. If fresh telemetry exists (within the 15-minute TTL window), it returns with sub-50ms latency.

PHASE 3
Live Sensor & Numerical Weather Prediction (NWP) Ingestion

On a cache miss, the server concurrently queries: (1) Open-Meteo High-Resolution NWP models for temperature, apparent feels-like, relative humidity, precipitation probability, surface pressure, cloud cover, wind speed, and direction; (2) Open-Meteo Air Quality API for US/European AQI, PM2.5, PM10, and ozone; (3) GDACS (Global Disaster Alert and Coordination System) for active tropical cyclone tracks and river flood telemetry.

PHASE 4
Algorithmic IMD Extreme Weather Risk Engine

The ingested numerical telemetry is evaluated by our deterministic mathematical risk engine modeled after India Meteorological Department (IMD) hazard standards. It computes a unified Risk Index (0 to 100) and assigns alert bands: Green (Low/Normal), Yellow (Watch), Orange (Warning), or Red (Severe Hazard). Specific physical triggers are checked (e.g. wind gusts > 62 km/h trigger Gale warnings; rain probability > 60% triggers agricultural irrigation rescheduling).

PHASE 5
Multi-Persona Context Grounding & Prompt Assembly

The backend injects verified telemetry metrics into a strictly formulated prompt. The system instructions explicitly order the model: "You are Weather SPT. Use ONLY the supplied sensor metrics. Strictly NEVER invent or estimate weather values. Provide operational advice tailored to the chosen persona."

PHASE 6
Domain-Trained AI Inference with Dual-Engine Fallback

The prompt is dispatched to our domain-trained AI engine (Gemini 2.5 Flash backbone fine-tuned on IMD meteorological handbooks and ICAR agricultural advisory bulletins). If the cloud network is unavailable or API quotas are exceeded, our Deterministic Indic Heuristic Fallback Engine automatically generates structured regional advice in Telugu, Hindi, Marathi, etc., ensuring 100% rural continuity.

PHASE 7
MongoDB Atlas Persistence & Continuous Dataset Logging

Fresh weather telemetry is saved in MongoDB Atlas with a native Time-To-Live (TTL) index set to 900 seconds. The question, synthesized response, language code, and user rating are logged into ai_conversations and formatted into training_dataset for continuous reinforcement learning from human feedback (RLHF).

PHASE 8
Multi-Platform Presentation & Audio Synthesis

The client application parses the JSON response. The Flutter app updates its AMOLED cards, animates the Doppler radar reflectivity canvas, and triggers the SpeechSynthesis engine to speak the advisory aloud in the user's selected regional language.

3.2 GeoJSON Point & 2dsphere Spatial Query Implementation

In MongoDB, weather data is stored with native GeoJSON coordinates [longitude, latitude]. When a user requests weather for a village, the server executes a spherical geospatial query:

// MongoDB GeoJSON $near Spatial Cache Check
const cachedDoc = await db.collection('weather_cache').findOne({
  location: {
    $near: {
      $geometry: {
        type: "Point",
        coordinates: [userLongitude, userLatitude]
      },
      $maxDistance: 5000 // 5,000 meters (5 km radius)
    }
  },
  expiresAt: { $gt: new Date() } // Ensures freshness within 15 minutes
});
Advantage for Rural India
In rural areas where cellular bandwidth is limited, farmers in adjacent fields query the same localized microclimate data. MongoDB's 2dsphere index allows the system to serve verified cache results in under 50ms without redundant external satellite API calls.

4. Domain-Trained AI & Anti-Hallucination Pipeline

4.1 Why Standard LLMs Fail at Weather

Generic foundation models suffer from stochastic generation—they generate numbers based on token probability rather than physical reality. If asked "Will it rain tomorrow in Kurnool?", standard LLMs may invent a temperature of 28°C and a rain probability of 40% based purely on hallucinated priors. In agriculture and disaster management, such hallucinations lead to catastrophic crop failure or unprepared evacuations.

4.2 The Strict Data-to-Prompt Grounding Protocol

Weather SPT completely decouples data acquisition from text synthesis. Telemetry values are acquired from scientific NWP models and injected as fixed constraints into the neural model's context window:

======================= STRICT GROUNDED SYSTEM INSTRUCTION =======================
You are Weather SPT, an AI meteorologist and disaster decision-support assistant.
LOCATION TELEMETRY (LIVE BOUNDARY CONDITIONS):
- Place: ${placeName} (Lat: ${lat}, Lon: ${lon})
- Temperature: ${temp}°C (Apparent: ${feelsLike}°C)
- Relative Humidity: ${humidity}%
- Wind Speed: ${windSpeed} km/h (Gusts: ${windGusts} km/h, Direction: ${windDir}°)
- Surface Pressure: ${pressure} hPa | Cloud Cover: ${clouds}%
- Air Quality: US AQI ${aqi} (PM2.5: ${pm25} µg/m³)
- IMD Extreme Risk Index: ${riskScore}/100 (${riskBand})
- Severe Weather Bulletins: ${JSON.stringify(alerts)}

RULES FOR GENERATION:
1. Use ONLY the numerical metrics provided above.
2. Strictly NEVER invent, estimate, or hallucinate numerical weather values.
3. Formulate the response naturally in the requested language: ${language}
   (en = English, te = Telugu, hi = Hindi, mr = Marathi, kn = Kannada, ta = Tamil).
4. Provide concrete operational directives (spraying window, irrigation advice).
==================================================================================

4.3 Domain Training & Fine-Tuning Corpus

The AI model backbone is adapted using domain-specific Indian meteorological corpora:

  1. IMD Standard Operating Procedures: Cyclone warning criteria, squall line definitions, and thunderstorm severity scales.
  2. ICAR & KVK Agromet Bulletins: Kharif and Rabi crop vulnerability matrices (e.g., foliar chemical drift thresholds for cotton, rice blast fungal humidity thresholds).
  3. Indic Vernacular Lexicon: Parallel translated meteorological terms across 6 Indian languages to avoid unnatural machine-translated phrasing.

7. Resilience, Edge Fallback & Deployment Process

7.1 Rural Continuity & Edge Fallback Strategy

Natural disasters and severe cyclones frequently disrupt rural cellular towers and fiber backhauls. A weather app that requires continuous cloud connectivity fails precisely when it is needed most. Weather SPT incorporates a Dual-Engine Resilience Model:

  1. PWA Service Worker Caching (`sw.js`): Intercepts network requests and caches the entire application bundle, UI assets, and icons locally.
  2. Embedded Database Fallback: If MongoDB Atlas cloud is unreachable, the Node.js server automatically routes reads and writes to an embedded SQLite database (weathergpt.sqlite) without raising exceptions.
  3. Deterministic Indic Fallback Matrix: If external LLM API endpoints time out or cellular access drops, our local expert rule matrix generates localized weather advice in 6 Indian languages directly from cached telemetry.
